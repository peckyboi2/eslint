## Intake contract agreed before coding (A03)

- Accept only `issues: opened` on the pinned public sandbox, default `main` code and matching workflow SHA, first run attempt. Ordinary User authors are eligible when the title starts exactly `Bug:`; Bot authors, PRs, closed/locked reports and missing/malformed identity fields are ineligible. Issue text never grants owner authority. Manual approval and stop require both original and rerun owner identity.
- Capture exactly title, body and a small snapshot containing repository/issue numeric IDs, number, author ID/type, created/updated timestamps and observed state. Maximum total staged UTF-8 is 65,536 bytes, reject rather than truncate. Supporting links are not followed; inaccessible linked content stays a model limitation. Initial live intake has no automatic support collection.
- Compare the event's opening snapshot with a fresh fixed-endpoint API response before staging, before inference and before approval/posting. Edits, labels that affect eligibility, closure, locking, transfer or deletion cause a silent failure; no edit/comment/reopen processing or automatic semantic retry. A final check cannot atomically lock GitHub against an immediately subsequent edit.
- The first unchanged eligible opening snapshot that wins transactional admission is final for that issue ID. Deduplication is repository ID plus immutable issue ID plus `opened`, independent of run ID, attempt, body hash or delivery. Admission separately binds the exact snapshot/input hash, workflow/code configuration and run. Reruns fail closed; crashes and failed inference keep reservations. No refunds or reuse of historical allowances.
- Keep hosted caps at 10 admissions per rolling 24 hours and 20 per campaign, reserved atomically on the dedicated state branch using expected-parent non-forced updates. One execution slot and GitHub `queue: max` allow at most 100 pending runs; no single-pending replacement. Overflow/cancelled-before-start events have Actions cancellation records only and may lack artifacts. Queue order follows waiting time, not issue order. No durable unbounded backlog is claimed.
- Skipped/edited/ineligible/quota-denied work produces internal audit when the job runs, without inference/public writes. For overflow or missing uploads, owner inspects Actions cancelled runs against issue creation history. Recovery is a separately authorised owner review of the original unchanged opening snapshot with a new bounded plan; never an automatic rerun, fresh quota reset or silent snapshot substitution. This candidate deliberately has no recovery trigger.
- Save `clarify`, `no_action` and `human_review` internally. Issue events have no posting job or issues-write permission. A separate future manual exact-output approval must bind repository/issue ID and number, source hash, input hash, validated output/comment hash, configuration SHA, preview run/attempt and code SHA. Fresh source/enabled checks, owner identity, bot identity, lifetime intent and uncertain-write reconciliation remain mandatory. Posting is disabled until a separately reviewed activation decision.
- Independent owner-only stop has no triage concurrency lock. It disables admission and workflow, cancels/force-cancels bounded active/pending runs and reports unresolved provider work and possible in-flight writes. Cancellation cannot refund reservations or guarantee provider cancellation/artifact upload.
